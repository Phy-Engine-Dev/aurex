# 独立任务与上下文隔离

从 2026-09-06 起，Web、管理员页面和社区入口的每个新请求均创建新的任务 ID 和会话 ID。

- 即使用户从旧会话页面提交，返回的也是新会话；前端按服务器返回的 ID 切换到该任务。
- 社区消息按评论身份去重，不再按“同一作者 + 同一实验”共享 agent 会话。重复拉取同一条评论只返回原收据，不重新执行或重复发送通知。
- 模型的普通上下文、压缩检查点、工具调用恢复和最终审核的降级读取全部限制到当前任务。
- 新请求仍可根据本次明确提供的实验目标重新获取社区原文；这不是继承旧 agent 的消息、摘要、工具结果或 HDL 工作区。
- 旧会话及任务保持历史档案，不删除、迁移或自动恢复。旧链接仍显示旧记录；新任务使用新链接。
- 单个任务内部的连续工具轮和该任务自己的压缩检查点保留。隔离针对不同请求，不是每次工具调用都清空上下文。

关键代码：`web.py`、`runloop.py`、`session_agent.py`、`context_budget.py`、`sessiondb.py`、`task_reply.py`、`tracking.html`。

回归：`test_fresh_sessions.py` 使用旧消息/旧摘要标记，验证它们既不进入首轮模型请求，也不进入最终审核；同时验证旧工具恢复不会污染新任务、旧文档与 HDL 工作区无法跨新会话读取。HTTP 和前端测试覆盖旧页面提交后返回/选中真正的新会话。
